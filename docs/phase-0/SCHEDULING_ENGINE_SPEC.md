# Adaptive Scheduling Engine Specification (v1.0-deterministic)

## 1. Deterministic Engine Core Architecture

The core scheduling engine operates **100% deterministically**. AI language models never directly construct time-blocks or assign study hours; AI only provides natural language summaries, advice, or explanations of schedule changes generated by the deterministic engine.

```text
Inputs:
├── Configurable Stored Target Exam Date & Timezone (system_settings)
├── User Constraints (Daily study hours by weekday, Blackout dates)
├── Curriculum Hierarchy (Lectures, Durations, Subject Weightages)
└── Student Performance Data (Topic Mastery, PYQ Accuracy, Retention Risks)
       │
       ▼
Deterministic Mathematical Scheduler (v1.0-deterministic)
       │  1. Compute Topic Base Priority & Efficiency Priority
       │  2. Allocate Daily Time-Blocks (60-min blocks)
       │  3. Insert Spaced Revision & Practice Blocks
       ▼
Outputs:
├── Today's Mission Tasks (Time-blocked)
├── Weekly Study Calendar
└── Backlog Recalculation Buffer
```

## 2. Topic Priority Mathematical Model (v1.0-deterministic)

Every GATE topic candidate $i$ receives a Priority Score calculated using readable, unambiguous named variables:

```text
basePriority =
  weightageFactor
  × knowledgeGapFactor
  × forgettingRiskFactor
  × errorFactor
  × prerequisiteFactor

efficiencyAdjustedPriority =
  basePriority / max(estimatedMinutes, minimumDurationFloor)

finalPriority =
  efficiencyAdjustedPriority
  + revisionUrgencyBoost
  + deadlineRiskBoost
  + backlogBoost
  - cognitiveLoadPenalty
  - contextSwitchPenalty
```

### 2.1 Factor Definitions and Allowed Ranges

1. **`weightageFactor`**: Range $[0.5, 2.5]$. Normalized weight of the topic's subject in the GATE syllabus (e.g. General Aptitude [15 marks] = $2.2$, Operating Systems [9 marks] = $1.8$, low-weight topic = $0.8$). Default = $1.0$ if unconfigured.
2. **`knowledgeGapFactor`**: Range $[0.1, 1.0]$. Defined as $(100 - \text{topicMastery}) / 100$. If topic has 0% mastery, factor is $1.0$. If 90% mastery, factor is $0.1$.
3. **`forgettingRiskFactor`**: Range $[1.0, 3.0]$. Derived from SuperMemo retention decay: $1.0 + 2.0 \times (1.0 - \text{retentionProbability})$. If card is due today, factor is $2.0$; if overdue by 7 days, factor is $3.0$.
4. **`errorFactor`**: Range $[1.0, 2.5]$. Ratio of recent incorrect PYQ attempts: $1.0 + 1.5 \times (\text{incorrectAttempts} / \text{totalAttempts})$. Default = $1.0$ if no attempts exist.
5. **`prerequisiteFactor`**: Binary $\{0.0 \text{ or } 1.0\}$. $1.0$ if all prerequisite subtopics are completed; $0.0$ if direct prerequisites are incomplete (prevents scheduling advanced topics early).
6. **`estimatedMinutes`**: Estimated duration of the lecture or practice task in minutes.
7. **`minimumDurationFloor`**: Hard floor set to $15$ minutes to prevent divide-by-zero or extreme priority spikes for tiny 2-minute tasks.
8. **`revisionUrgencyBoost`**: Range $[0, 50]$. $+30$ points if topic is marked due in the spaced repetition queue today; $+50$ points if overdue $\ge 3$ days.
9. **`deadlineRiskBoost`**: Range $[0, 40]$. Dynamic boost proportional to remaining days before exam: $40 \times (1.0 - \text{daysRemaining} / \text{totalPrepDays})$.
10. **`backlogBoost`**: Range $[0, 35]$. $+35$ points if the task was assigned to a previous daily mission but marked `SKIPPED` or uncompleted.
11. **`cognitiveLoadPenalty`**: Range $[0, 20]$. $-15$ points if 3 consecutive heavy theoretical blocks have already been scheduled today (prevents burnout).
12. **`contextSwitchPenalty`**: Range $[0, 15]$. $-10$ points if the candidate task belongs to a subject different from the preceding task in the same session.

### 2.2 Clamping, Normalization & Tie-Breaking Rules

* **Final Clamping**: $finalPriority$ is clamped to the range $[0.0, 1000.0]$.
* **Tie-Breaking Rule**: When two candidate topics have identical $finalPriority$ scores (within $\pm 0.01$):
  1. Higher `weightageFactor` wins.
  2. Lower `topicMastery` wins.
  3. Earliest `lecture_order` wins.
* **Algorithm Versioning**: Every generated schedule stores `algorithm_version: "v1.0-deterministic"` in the `study_missions` metadata column.

### 2.3 Why This Is a Starting Heuristic
This formula is an empirical prioritization heuristic designed for operational study scheduling. It is **not** presented as an academically proven or peer-reviewed rank predictor. Coefficients ($w_1..w_n$) are fully configurable in `system_settings` and subject to calibration during Phase 4 testing.

## 3. Backlog Recovery & Conflict Resolution Rules

1. **Missed Task Protocol**: If a scheduled lecture or practice task is uncompleted by 23:59, it transitions to `BACKLOG` state.
2. **Buffer Allocation**: Weekend buffer blocks automatically absorb unfinished high-priority backlog tasks.
3. **Manual Task Locking**: Locked calendar blocks are respected without overwriting.
4. **Deterministic Fallback**: If the external AI service is unreachable, the UI displays the exact mathematical explanation: *"Rescheduled Data Structures practice because topic retention risk rose to 78%."*
